SharpForge Studio 0.9.0 — static browser build

Serve this directory with an HTTP/HTTPS static server; open index.html from that origin. ES modules and real compiler/runtime workers must be allowed. A separate SharpForge-standalone.html embeds scripts/styles and Blob workers without server assets. No backend or .NET installation is required for the browser compiler preview. Native MSBuild operations require the separate local Node host and an installed SDK/MSBuild toolchain.

Open the containing folder for .csproj/.slnx projects. Required sibling files must be explicitly selected or within the selected folder. Project Properties selects entry/startup/configuration. This is a bounded project subset: references are source-combined, not separately linked; MSBuild tasks, NuGet restore and binary linking do not run in portable browser mode. The native host delegates these operations to installed build tools. Native folder handles support explicit permission/conflict-checked source saving; file-input fallback supports read/export only.

All 27 tools are separate docking panels. Drag tabs to group centers or edges, split documents, resize, float, auto-hide/pin, save named layouts or open tools/documents in separate browser windows. Independent editor buffers and undo histories survive moves. The main application must remain open for popouts.

Assembly Explorer has its own Open DLL / EXE action, without replacing the current source project. Inspect metadata and full method IL, choose a method, enter JSON arguments, Verify and Invoke. Edit IL uses the metadata-preserving SharpForge.IL/1 dialect and runs rebuilt bytes. Unsupported runtime features remain inspection-only; conservative C# reconstruction falls back to method IL.

Examples includes 29 source cases (28 executable and one deliberate diagnostics case); examples/projects contains bounded disk workspaces, and examples/managed contains DLL/EXE/IL fixtures. New language features include partial classes, nameof and library targets. Find in Files has validated replace-all; Call Hierarchy is bound to source methods. Ctrl+. shows supported code actions; Shift+Alt+F formats indentation; Ctrl+/ toggles comments; Alt+Up/Down moves lines.

Generators & Analyzers and Generated Sources are docking tools. Extensions are trusted JavaScript callbacks, not Roslyn analyzer DLLs. Export projects for durable backup. This preview is not full C#/CLR/MSBuild/Visual Studio parity. See docs/validation.md, docs/project-system.md, docs/docking.md and docs/managed-il.md for exact contracts and unverified browser/native-runtime boundaries.

0.6 adds checked int32 arithmetic/constants, concrete IDisposable using cleanup, and per-project checked defaults. Debug IL optionally records bounded reverse history; Step back/Reverse continue restore managed state, and local/object context menus configure write breakpoints. The syntax/gutter overlay renders the viewport; the full native text buffer and lexical scans remain. New structural actions, selection expansion/shrinking, Back/Forward navigation, immutable schema constructors and analyzer severities are included. See docs/release-0.6.0.md and docs/validation-0.6.0.md for tested scope.

0.7 adds native MSBuild, MSBuild Evaluation and Project Source docking tools. Start the local same-origin host from the source distribution: npm run msbuild -- serve --root "/path/to/workspace" --studio dist --trust-projects. Open the exact session URL printed by the host, choose Use native workspace and enable trust after reviewing the project. Build/restore/pack/publish/test/custom targets, evaluation/target results, preprocessing, diagnostics and DLL inspection use the installed engine. Native tasks and evaluation can execute with your OS permissions: this is not a sandbox, and the service must not be exposed publicly.

Native disk XML is saved with hash conflict checks rather than being flattened; SLNX structural inspection is data-only. Standalone HTML alone cannot launch native MSBuild. The real-SDK gate was unavailable in the release environment (no dotnet); local process/HTTP tests use a labeled simulator, and new browser controls use a labeled client test double. See docs/msbuild.md, docs/release-0.9.0.md and docs/validation-0.9.0.md for startup, exact tested scope and compatibility boundaries.

0.8 adds a virtualized Solution Explorer hierarchy, project/file commands, all-tool context menus, selected-item Properties, and Environment / Keyboard. Visual Studio is the default source-editor profile; Vim, Emacs, Sublime and a VS Code shortcut preset are selectable. Alternative modes use the locally bundled, MIT-licensed CodeMirror 5.58.3 snapshot; see THIRD_PARTY_NOTICES.md. This is not native Vim/Vimscript or full Visual Studio parity. XML/IL textareas do not use the modal editor profiles.

Browser explorer changes edit in-memory records; Export workspace preserves XML, source, DLL bytes and settings. Actual rename/copy/delete/undo on disk requires the separate native host. Multi-file native changes are conflict-checked and quarantined for bounded undo, not atomic transactions or OS file locks. Build trust is separate from permission to edit files. Read docs/explorer-keymaps.md and docs/validation-0.9.0.md for exact capabilities and validation scope.
