# Scrolling, adaptive panels and control event acknowledgements

The A16 scrolling contribution shares one layout model between direct JavaScript, source VM and CIL execution. Browser input and painting consume the same viewport geometry. Offsets are unscaled content DIPs; viewport dimensions are arranged DIPs. The resulting child transform combines zoom and negative content offsets. Managed layout, pointer hit testing, DOM placement and retained rendering consume that transform.

## View operations

`ScrollViewerModel` implements nullable `ChangeView` arguments, extent and zoom clamping, disabled axes, direct interaction and disposal. `ScrollViewModel` adds correlation IDs, scroll/zoom options and snap points. Programmatic animation samples a cubic-out curve over 180 milliseconds by default. It publishes intermediate `ViewChanged` events and publishes the final `ViewChanged` before the corresponding completion. Replacing or disposing an operation reports `Interrupted` exactly once; unchanged requests report `Ignored`.

`ScrollingAnimationMode` is `Disabled=0`, `Enabled=1`, `Auto=2`. Auto consults the live environment animation preference. Explicit Enabled preserves the caller's choice. `ScrollingSnapPointsMode` is `Default=0`, `Ignore=1`. Repeated snap points use arithmetic bounds rather than materializing their potentially large range; the snap collection itself is limited to 2,048 entries. Zoom centers remain anchored after selecting the snapped zoom factor.

The browser host owns completion for a live worker session. The VM emits `{op:'layout', id, method, args, correlationId}` and returns that same ID. The host completes the actual animated operation; the VM consumes the final event and its metrics before running managed handlers. Headless execution uses the same model with an injected frame clock. There is no second VM animation completing ahead of the browser.

`layoutSnapshot()` includes each viewport's extent, viewport, offsets, zoom and current anchor. Native `ViewChanged`, `ScrollCompleted` and `ZoomCompleted` payloads include finite read-only metrics. `serializeRoutedEvent` preserves these data fields through structured cloning. The native event bridge processes these updates even if the application has not subscribed to the corresponding event.

## Input and templates

The scrolling renderer contains one clipped content part and accessible horizontal and vertical range parts. Auto, visible, hidden and disabled scrollbar modes are distinct. Wheel input bubbles through a managed descendant to its scrolling ancestor; reaching an edge permits the next ancestor to consume it. Line and page deltas are converted using measured font size and viewport size. Ctrl-wheel zoom preserves the point under the pointer when zoom is enabled.

Touch input starts panning after four DIPs, captures the active pointers, and cancels the pending tap gesture. A second captured touch supplies a centroid and distance for pinch zoom. Arrow, page, Home and End keys operate the focused scrolling surface without intercepting a native editor's keys. These browser pointer operations do not claim OS precision-touchpad inertia or native compositor gesture parity.

Anchor candidates can be explicitly registered or marked with `CanBeScrollAnchor`. The layout engine records the chosen descendant's content position and compensates its offsets after insertion or resizing above that descendant. Candidate selection uses the configured viewport anchor ratios. It is bounded to 2,048 candidates and a 20,000-node traversal. Source geometry changes invalidate dependent ParallaxView arrangement, including sources that occur later in painter order.

Expander retains separate managed `HeaderPresenter` and `PART_BehaviorRoot` template parts. The header remains a native keyboard-operable button; content occupies a separate arranged slot. Collapsing suppresses the private layout slot while retaining the caller's Visibility value. Up and Down are implemented. Previously released Left and Right enum values produce `SFLAYOUT006` instead of being silently treated as Down. Opening uses a cancelable browser clip/opacity animation when animations are enabled; collapse immediately updates layout. Native composition animation equivalence requires separate qualification.

TwoPaneView computes independent pane rectangles and publishes ModeChanged when the resulting SinglePane, Wide or Tall mode changes. NavigationView and SplitView register their family-owned pane/content layout contributions through `registerNavigationLayouts`. They share named managed presenters with the family renderer instead of relying on unrelated DOM-only rectangles.

## Native interaction state and asynchronous events

### AnnotatedScrollBar

AnnotatedScrollBar has an independent vertical rail, a fixed-height noninteractive thumb, increment/decrement buttons, keyboard operations and offset labels. Label layout preserves the first label and removes overlapping upper labels with four DIPs of separation. Labels are clipped when their text exceeds the available width. Click and drag requests raise cancelable Scrolling before requesting a viewport move. DetailLabelRequested can supply content for a wrapped tooltip capped at 360 DIPs. LabelTemplate and DetailLabelTemplate use real managed containers created by the shared ItemContainerGenerator. Template binding, data context, recycling, snapshot retention and disposal follow the existing A15 template engine.

The native `ScrollController` property returns a typed IScrollController implementation with SetValues, SetIsScrollable, completion notification and current state. It connects to a real ScrollPresenter through HorizontalScrollController or VerticalScrollController. The ScrollView default template contains a real named PART_ScrollPresenter; ScrollView.ScrollPresenter returns that managed part after template application. Both the outer API and the presenter's API operate the same viewport and the transform is applied once. Existing direct ScrollView scenes continue to own their viewport directly.

This controller runs on the UI thread and returns null PanningInfo, which is the optional native composition-panning connection. GetScrollAnimation preserves the supplied default animation. A custom IScrollController requires an explicit adapter rather than being treated as an annotated controller. ControllerStateChanged is an additive browser-profile event carrying six bounded fields so worker code observes the actual range and mouse state. These limitations are separate from the native interface metadata inventory.

`tests/a16-annotated-scrollbar.test.js` contains authored overlap, cancellation, disposal, synchronous completion and real-template ownership fixtures. Microsoft's [AnnotatedScrollBar guidance](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/annotated-scrollbar) supplies the behavioral reference. Native private template geometry and compositor inertia have not been captured by these model fixtures.

`createLayoutTemplateServices(context, {createGenerator})` composes auxiliary label content without adding a controls-to-properties package dependency. The application injects its ItemContainerGenerator factory after initializing its item-container adapter. Property and Labels collection changes call `changed` and `collectionChanged`; visual preparation calls `prepare` before traversing children. `prepareDetail(owner, outcome)` runs after managed handlers and deferrals finish, before exporting the event outcome. The resulting Content is a real managed container, so it receives ordinary visual preparation too.

Existing `$itemContainers` ownership retains the generated visuals. The bounded `$layoutTemplates` scene projection contains only their identities, and `scene(owner)` supplies the same projection for complete snapshots. At most 2,048 labels and one detail container are retained. The renderer consumes those visuals; it does not instantiate templates or interpret managed code. `tests/a16-layout-templates.test.js` covers generator reuse, data context, replacement, detail cleanup, malformed projections and snapshot identity. An incomplete raw scene with an assigned template but absent prepared visuals reports `SFTPL018`; normal registered DataTemplate flows are prepared by the application service.

AnnotatedScrollBarLabel.Content and ScrollOffset are constructor values with getter-only contracts. Replace a label through Labels to change them. Properties on a label's Content data object use the DataTemplate's ordinary binding subscriptions and disposal lifetime. The auxiliary service adds no global owner or label subscription. It accesses `context.state` before mutations so the managed and JavaScript transaction journals capture both generators. Restoring those snapshots reuses existing identities without running factories. Managed owner synchronization retains recycled containers as well as visible ones; phase work uses the existing owner scheduler.

The root-owned input tracker publishes `{id, properties:{IsPointerOver?, IsPressed?, FocusState?}}` through `onControlStateChanged`. Batches contain at most 256 nodes; values are booleans or FocusState 0–3. The callback precedes native route dispatch and visual-state application. Template owners receive physical descendant hover and press state, and multiple pointers cannot release one another's press. A cached ancestor evaluation keeps refresh work linear in visited ancestry.

`host.requestEvent(id, eventName, payload, {signal})` and `context.requestEvent(nodeOrId, ...)` await `options.onEventRequest`. The outcome is data containing fields such as Cancel and Handled. At most 64 requests may be pending and each has a 30-second deadline. Caller cancellation, target removal, root reset and host disposal abort outstanding work. The local fallback emits synchronously and resolves the payload; an application hosting managed deferrals supplies the acknowledgement hook. Input objects, functions, cycles and unbounded payloads do not cross this boundary.

## Contracts and qualification

Existing released signatures and enum meanings remain locked. In particular, SharpForge's released Orientation uses Vertical=0 and Horizontal=1, unlike the native WinUI enumeration. The new scroll content-orientation and option enums use their native meanings. This difference is recorded rather than silently changing persisted application behavior.

Focused fixtures are authored in `tests/a16-layout-scrolling.test.js`, `tests/a16-scroll-runtime.test.js`, `tests/a16-input-visual-state.test.js` and `tests/a16-host-event-requests.test.js`. Browser cases are collected by `tests/browser_a16_controls_test.py`. Execution is deferred to the coordinated completed-scope validation gate. Authored fixtures are not passing results or native parity evidence.

The pinned metadata reference is Windows App SDK 1.8.260921001. Behavioral references include Microsoft's [ScrollView guidance](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/scrollview), [ScrollViewer guidance](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/scroll-controls) and [Expander guidance](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/expander). Browser measurements and native Windows GUI/assistive-technology captures must be reported separately.
