Raw reports are in this directory; `validation-0.10.0.json` indexes the suite results. All ten new examples execute through internal IR, canonical CIL reload, direct CIL and exported/reassembled IL. Tests also check Studio and disk example source equality. AsyncWorkshop, SymbolWorkshop and WinUICounter disk `.slnx`/`.csproj` previews execute through the CLI. WinUI CLI execution produces a scene; interactive rendering is tested in the browser host.

## What the browser checks establish

Existing samples, exact Fibonacci breakpoint stops, source edits, editor modes, 12,000-line viewport rendering, reversible DLL debugging, native file create/rename/copy/delete/undo/conflict checks and docking are rerun. The new suite verifies symbol source without replacing the project; explicit evaluation consent/preview/commit; successful and rejected Hot Reload; guarded relocation; suspended task inspection and freeze/thaw; actual WinUI events/input synchronization; async handlers; managed callback breakpoints; direct-IL UI execution; standalone JavaScript namespace constructors/events; Canvas2D pixels; DOM fallback; and all seven new docked tools.

The main browser uses production modules and actual workers in an in-memory origin because normal HTTP navigation is blocked by runner policy. Storage is an in-memory test shim, not durable-storage qualification. The native explorer suite talks through a byte forwarder to the production HTTP host and real temporary filesystem; it is not a file-operation mock. The MSBuild-client acceptance suite uses a labeled native-client test double, and lower adapter tests use a labeled process simulator. Neither substitutes for native SDK execution.

The standalone HTML is injected into about:blank; real Blob workers run, with no CDN/module fetches. Normal file-origin policy, HTTP-origin loading, native picker dialogs and durable storage have not been qualified.

## Symbols and compatibility evidence

The Portable PDB reader processes an independently sourced Microsoft fixture with 13 documents and hidden/multi-document sequence points. Its exact Git blob and license are checked. Hash algorithms and DEFLATE are independently compared to Node crypto/zlib. Generated sidecar/embedded PE identity and checksum validation, scoped locals, wide indexes, bad inputs, wrong symbols, and verified source coordinates are tested.

The `PortableSymbols.dll` example is generated by SharpForge without its private #SF stream. It is not misrepresented as an independently Microsoft-compiled DLL. Native Visual Studio/CLR consumption of SharpForge-emitted PDBs, general Roslyn async state-machine execution, Windows/native PDBs and broad third-party DLL compatibility remain unqualified.

## Rendering evidence

The WinUI browser tests read actual Canvas2D pixels and verify DOM fallback. They separately test unavailable-WebGPU negotiation and independent JavaScript events. A real WebGPU shader/pipeline implementation is included, but this runner has no usable WebGPU adapter. Hardware rendering, adapter-specific behavior, device loss, power/performance and high-DPI/mobile GPU qualification are not established by these tests. HTML remains the text/control renderer; this is not a full GPU WinUI compositor.

## Performance regression found and repaired

The large-source browser gate initially failed because PDB emission and source binding rescanned the document for every point. Per-document line indexes and method-grouped points replaced those quadratic scans. A 12,000-statement fixture now asserts every selected source mapping exactly; the complete legacy 12,000-line editor suite passes. A local single-run Node observation changed compilation from roughly 12.7 seconds before the fix to roughly 0.51 seconds after, with binding about 14 ms; these are development observations, not statistically qualified cross-machine benchmarks.

## Reproduce

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm run check
npm test
npm run build
npm run test:packages
npm run standalone
CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:standalone
CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:browser:advanced
# Set SHARPFORGE_IN_MEMORY=1 only on restricted runners for older HTTP-default suites.
```

A separate final-archive verification log accompanies the release downloads. It records extraction of the delivered ZIP, source-manifest verification, offline install, the full tests/check/rebuild, CLI examples, and byte comparisons of the rebuilt standalone and package tarballs. No GitHub deployment, registry publication or hosted-CI success is claimed.
