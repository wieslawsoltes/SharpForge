# Explorer operations with prepared source models

Solution Explorer stages browser file operations through `ExplorerTransaction`. Existing sources retain their model and immutable current snapshot; cloning records no longer reads their enumerable `text` compatibility getter. Source copy and rename use the editor's public URI-rebase seam. Source writes create a separate staged model, so a later invalid operation cannot modify the live document before commit.

The host still implements `commit({records, folders, mappings, restore, entry})`. The payload also includes an optional `documentStates` Map. The Studio host supplies `captureDocumentState(uri)` through `documents.captureState(uri)` and `ownsModel(model)` through the document owner. It passes the Map unchanged to `documents.replace` with `preserveDirty: true` and an explicit discard decision for replaced/removed documents. The document owner validates every state against the incoming URI, version and exact source before transferring ownership.

`documentStates` entries contain `{uri, version, source, baseline, dirty, staleSave}`. Sources and non-string baselines are immutable snapshots. New or copied source files have an unsaved baseline of `null`. Renaming a dirty source rebases its saved baseline while retaining the unsaved content. Clean moved sources retain a matching clean snapshot. File-operation undo restores the captured baseline and dirty state. Unchanged models retain their shared editor undo history; models at a changed URI are newly created from the persistent snapshot, and file-operation undo restores the captured source rather than reviving a disposed model.

History captures immutable source roots without live models. It detects newer document edits by snapshot identity, avoiding full-text comparisons. Unrelated, unchanged documents keep their existing model during undo. Binary history still copies the bounded byte buffers because those buffers are mutable. History retains at most 32 operations; when the estimated retained source size exceeds 32 MiB it drops older entries while preserving the most recent undo. The estimate uses snapshot lengths, never full-source materialization.

Collision checks use indexed path-prefix counts and case-folded names. Bulk creates inspect path components rather than repeatedly scanning every workspace file. Workspace content is bounded by the existing Studio limits: 20,000 files, 256 MiB per source buffer and 320 MiB total source units; the logical storage estimate counts two bytes per source UTF-16 unit. No speedup is claimed without a benchmark.

Browser Add Existing Item reads C# files through `readStudioSource` (or the host's equivalent `readSource` callback), including cancellation checks and bounded byte slices. It no longer routes prepared sources through a whole-file byte array or base64 string. Other file types keep the archive decoder. Native file creation retains the existing protocol's 16 MiB binary payload limit; native text writes retain their 4 MiB limit. Oversized native operations fail explicitly before native mutation I/O.

Browser operations also accept `{kind: 'create' | 'write', path, record}`. Project import callers pass the prepared record directly instead of spreading it into `{text}`. Caller-supplied models remain caller-owned if preparation fails. Models created inside a transaction are disposed on failure, and unused intermediate models are released after success. Add Existing Item owns its newly read models until adoption and cleans them up if any later file, project edit or commit fails.

After `DOCUMENT_COMMITTED` errors, the document owner retains the adopted models. The host finishes its matching metadata commit before rethrowing that error. Explorer then retains the completed operation in history and never disposes adopted models. `ExplorerCommands.dispose()` cancels a pending source import and releases retained history; the Studio host calls it when its command composition ends.

## Qualification

The focused scope includes `a19-explorer-snapshots.test.js`, `a19-explorer-source-plans.test.js`, `a19-document-operation-state.test.js` and `a19-document-disk-save.test.js`. They exercise real EditorModels and chunked File reads, a source above the previous 16 MiB limit, dirty rename/copy/undo, stale-undo refusal, failed/cancelled imports, postcommit errors and the captured DocumentService-to-DiskWorkspace stream boundary in UTF-8, UTF-16LE and UTF-16BE. Execution results are recorded after the complete-scope validation slot. Browser file pickers, permission dialogs and the final Studio host composition are separate integration qualification.
