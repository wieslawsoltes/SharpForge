# Typed method body contract v1

`methodBody(method, 'bytecode', {image})` and `methodBody(method, 'cil', {inspector})` export the same operation vocabulary. Metadata context is mandatory. Missing context produces SCHEMA_CONTEXT; unsupported opcodes, uninstantiated generic signatures and filter/fault execution regions produce SCHEMA_UNSUPPORTED. The lowerer does not reinterpret unknown instructions as no-ops or claim executable types from stack heights alone.

Each instruction has a normalized opcode, semantic operands, concrete inputTypes/outputTypes, stackIn/stackOut and successors. `resultType` is the last output type or `void` when there is no output. Duplicate explicitly has two output types. Offsets are zero-based instruction indices. sourceOffset/sourceOpcode/sourceEncoding retain provenance only; branch operands, successors, handlers and safepoints are normalized indices. Calls carry resolved target signatures, and fields carry declaring owner/name/storage type.

Stack categories are i32, i64, nativeint, f32, f64, null, ref:Type, byref:Type and pointer:Type. Narrow integer/bool/char storage uses i32 on the evaluation stack; localStorageTypes, parameterStorageTypes and returnStorageType preserve declared storage widths. f32/f64 stack joins widen to f64. Equal concrete types join unchanged; null joins a managed reference to that reference type. Reference joins use compatible base/reference types, widening unrelated references to System.Object. Numeric/reference and incompatible-width joins fail with SCHEMA_TYPE_CONFLICT. Stack-height conflicts also fail. Source constant double hints are retained, and declared storage/call/return signatures permit the source numeric carrier's Int32-to-floating widening. Stores return their declared storage category when retainValue is true. No inferred type is `any` or null JSON; polymorphic builtin parameter *constraints* may be any/array/number, but actual instruction inputs are concrete.

The worklist starts at method entry and every catch/finally entry. CIL catch entry receives its resolved exception type on the stack; source catch entry has an empty stack because its exception goes directly into the declared catch local. Finally entry/exit stacks are empty. Independently unreachable compiler epilogues are also checked from an empty block-entry stack; malformed dead instructions cannot acquire invented types. Calls consume parameters in stack order (receiver first for instance calls). Returns must consume the complete stack and match the method signature.

Source stores retain the assigned value; CIL stores do not. Normalized store operands explicitly carry retainValue. Source void calls produce a null padding value consumed by subsequent source operations; call.voidResult and return.discardPadding expose that behavior without making the target signature non-void. Source source-range end markers that participate in finally leave semantics become a half-open protected range including the terminal branch. Every source leave records the finalizer regions crossed. These distinctions are semantic operands, not hidden dispatch based on provenance.

Supported lowering covers the source bytecode operation set, direct CIL numeric/local/argument operations, conditional/unconditional/switch control flow, calls/constructors/function addresses, managed object/array/field/static access, casts/boxing and catch/finally exits. Indirect memory operations are explicitly rejected until address lifetime proofs are provided. `calli`, unresolved generics, general filter/fault dispatch and unrecognized opcodes are rejected. This contract does not claim that a new managed runtime executes the exported IR; it supplies validated, executable-typed semantic input for one.

`validateBody(body,{requireExecutable:true})` is the reader gate: it checks resolved concrete types, operation membership, typed stack effects, declared local/argument load types, edge joins, target bounds, maximum stack and exception entry stacks. Structural JSON schema additionally rejects a resolved record with null result annotations. Tests cover all methods (including generated helpers) of parked-frame, native-callback and nested-finally in both encodings, plus mixed-type joins, mismatched effects, unsupported instructions and malformed offsets. Existing JS interpreter execution fixtures independently prove the behavior of those source programs.
